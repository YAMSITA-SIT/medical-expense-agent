## テスト（DB・APIキー不要）
Node.js 24以上を使用してください。外部npm依存はありません。
```sh
cd current-demo/benefit-agent
node restore-knowledge.mjs
npm test
```

## 職員画面の起動
1. 専用のSupabaseプロジェクトでbenefit-agent/supabase.sqlを実行します。
2. current-demo/triage/.env.exampleを同じ場所の.envへコピーし、専用プロジェクトのURL、サーバー専用秘密キー、任意のデモ用tenant IDを設定します。既存環境のキーは同梱していません。
3. benefit-agentでnpm run seedを実行して架空の基本案件を登録します。専用ケースのfixturesとreleaseスクリプトも同梱しています。releaseスクリプトは内容を確認してから実行してください。
4. benefit-agentでnpm startを実行し、http://127.0.0.1:4176/ を開きます。

.envはサーバーが参照する設定です。ブラウザやGitへ公開しないでください。正式決定・送金・本番の職員認証は対象外です。

## 根拠文書
knowledge/には出典URL・適用範囲・抽出テキストを同梱しています。原本PDF/HTMLの複製は配布物に含めず、manifest.mjsとnational-sources.mjsのURLから取得してください。文書検索を新しいDBで使う場合は原本と検索区間の登録が別途必要です。既存DBの内容や職員編集を自動で復元するものではありません。抽出テキストの登録だけで算定上の検証済みとはしないでください。

## スナップショット
ソースのロジックは現時点のまま収録し、新機能や法令上の網羅性を追加したものではありません。秘密キー、個人設定、DBダンプ、作業ディレクトリ、仮想環境、Git履歴、利用者が提供したPDFは除外しました。

文書抽出データ2件は転送量を抑えるためgzip＋Base64分割で同梱しました。restore-knowledge.mjsで元のJSONへ復元してからテスト・起動してください。
